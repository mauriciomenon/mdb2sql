## TECHNICAL NOTES

### DuckDB Choice Rationale
- Embedded (no server process)
- ATTACH multiple databases in single query
- Analytics optimized (fast aggregations, joins)
- Native bindings: Rust (duckdb crate), Go (go-duckdb), Python (duckdb-python)
- Column-oriented storage = fast for our use case

### XP Cycle Reminder
Understand -> Code -> Fix -> Add Feature -> Refactor
- Never rewrite entire modules
- Extend existing functionality
- Refactor only for clarity/performance of working code

### Code Documentation Template
```

# Este codigo faz X porque Y.
# Exemplo: conecta ao banco usando DuckDB que permite...
```

### LEARNINGS

**Go + Wails:**
- Wails auto-exposes exported methods on App struct to frontend
- window.go.main.App.MethodName() pattern in React
- TypeScript declarations needed for Wails bindings
- go-duckdb uses standard sql.DB interface

**Rust + Tauri:**
- #[tauri::command] macro exposes functions to frontend
- Mutex<T> required for State shared across commands
- duckdb::types::ValueRef needs explicit type matching for JSON conversion
- Tauri requires build.rs and tauri-build dependency
- Icon files needed even with bundle disabled

**Svelte Reactivity:**
- $: reactive statements auto-run when dependencies change
- bind:value creates two-way binding
- class:name={condition} for conditional classes
- Scoped styles by default (no CSS conflicts)
